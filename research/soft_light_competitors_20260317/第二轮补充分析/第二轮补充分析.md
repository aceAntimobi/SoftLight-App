# 第二轮补充分析

生成时间: 2026-03-17

## 1. 补样目标
- 第一轮样本以白屏工具型产品为主，能说明赛道低门槛和广告化现状，但不够贴近 `Soft Light` 的柔光体验方向。
- 第二轮重点补充更接近 `夜灯 / 阅读灯 / 场景灯 / 柔和补光` 的样本，用来验证更合理的交互深度和功能边界。

## 3. 核心发现
### `com.display.light.TableLamp`
- 运行态已抓到真实主界面，信息完整度最高。
- 首次进入有教程，教程直接教用户“向下拖动降低亮度”，说明它把手势学习当成核心能力。
- 主界面保留大面积灯光区，底部是 `Timer / Color / Relax / More` 四个入口，中间单独展示亮度值。
- 这类产品不是纯工具，而是“照明 + 放松场景”混合体。
- 风险也很明显: 首次教程打断较重，底部功能入口已经偏多。

### `com.studio360apps.screen.flashlight`
- 安装运行成功，但启动后被导到 `com.android.vending` 登录页，运行态不可作为交互依据。
- 静态包信息显示:
  - `version_name = 1.2.3`
  - 含 `com.android.vending.BILLING`
  - 含广告与归因相关权限
  - 字符串中出现 `candleEffect`、`sleepTimerMinutes`、`BrightnessGestureLearned`
- 这说明它不是简单白屏，而是包含烛光效果、亮度学习、睡眠定时的轻灯效产品。
- 但它对 Play 商店链路依赖较重，稳定性和首开体验存在风险。

### `com.ryosakata.reading_light`
- 运行态可用，而且界面非常干净。
- 顶部直接给 4 档色温/颜色位，UI dump 里能读到 `warm` 和 `cold`。
- 中段有 `Sleep Timer`，旁边是增减控制。
- 中央是大号数值亮度显示，当前显示 `0 / min`，底部是单一主操作按钮。
- 这是一个很接近“极简阅读柔光灯”的参照物，结构比 `TableLamp` 更轻。
- 从功能取舍上看，它更像 `Soft Light` 高级面板的精简版。

## 4. 对 `Soft Light` 的直接启示
- `TableLamp` 证明“全屏灯光 + 底部工具条 + 手势亮度”是成立的，但它功能入口过多，不适合直接照搬。
- `Reading Light` 证明“少量色温档 + Sleep Timer + 单一主操作”足以支撑一个轻量但不廉价的产品。
- `studio360` 说明柔光工具赛道经常把广告、商店链路、烛光特效混进来，但这样会伤害启动稳定性。

## 5. 推荐取舍
- 保留:
  - 全屏优先
  - 左右切换模式
  - 上下亮度手势
  - 定时关闭
  - 高级面板中的色温/色盘
- 不建议直接引入:
  - 首次教程页
  - 多 Tab 底部导航
  - 放松音乐模块
  - 强依赖商店或外部推广链路

## 6. 结论
- 第一轮告诉我们: 赛道主流很粗糙，广告重。
- 第二轮告诉我们: 真正值得借鉴的不是白屏工具，而是“轻场景 + 柔光体验 + 少量高级控制”。
- `Soft Light` 仍然应该坚持现在这条路:
  - 主界面极简
  - 默认即点亮
  - 手势优先
  - 高级控制收纳到抽屉或图标展开
