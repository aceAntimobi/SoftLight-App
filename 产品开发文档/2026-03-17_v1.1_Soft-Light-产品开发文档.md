## 1. 产品概述
### 1.1 产品目标
- 将 `Soft Light` 从“白屏照明工具”升级为“高质感屏幕柔光灯”。
- 建立三个清晰认知:
  - 默认即点亮
  - 手势即控制
  - 柔光模式有审美而不是纯工具参数
- 在当前版本内完成一套可稳定打包、可在安卓模拟器运行、视觉统一的 MVP。

### 1.2 目标用户
- 夜间起夜和轻照明用户
- 自拍 / 拍照补光用户
- 睡前陪伴和婴儿夜灯用户
- 阅读、专注、桌面氛围用户

### 1.3 核心价值
- 柔和纯色，不刺眼，不做手电筒式高对比强光
- 单屏完成主要操作，不依赖复杂导航
- 支持预设模式、亮度手势、自定义色盘、定时关闭、多语言自动切换

### 1.4 当前版本范围
- 目标版本: `Soft Light v1.1` 开发交付版
- 平台优先级:
  - P0: Android APK 构建、模拟器安装与运行
  - P1: iOS 工程保持可继续打包
- 商业化范围:
  - 本轮不接广告 SDK
  - 本轮不接内购 SDK
  - 仅保留未来扩展位和埋点占位

### 1.5 关键输入缺口与本轮假设
- PRD 未明确 `定时档位` 的最终列表，本轮假设为 `15 / 30 / 45 / 60 分钟`。
- PRD 提到 `Pro / 广告规则`，但未要求当前必须接入真实商业化，本轮按“结构预留、不接 SDK”处理。
- PRD 提到 `自定义模式最多 N 个`，本轮假设 `N = 8`，超出时采用覆盖最早项策略。

## 2. 功能框架
### 2.1 一级功能模块
- 灯光核心引擎
- 模式与手势控制
- 手动色盘与自定义模式
- 定时关闭
- 本地化与状态恢复
- 品牌与视觉系统

### 2.2 二级功能拆解
#### A. 灯光核心引擎
- 预置 12 个默认柔光模式
- 默认排序突出 `浅白 / 米白 / 粉色 / 暖黄色`
- 灯光区域接近全屏
- 输出纯色，不使用上下渐变，不保留灰色边缘阴影

#### B. 模式与手势控制
- 左右滑动切换模式
- 上下滑动调节亮度
- 当前亮度有轻量文本反馈
- 底部模式控制压缩为单行滚动控制条

#### C. 手动色盘与自定义模式
- 控制条只展示图标入口
- 点击图标弹出底部毛玻璃抽屉
- 支持色盘选色、应用当前颜色、保存为自定义模式
- 自定义模式支持删除和再次选择

#### D. 定时关闭
- 主界面提供定时入口
- 支持常用时间档位
- 倒计时结束自动熄灯并恢复可见 UI 状态

#### E. 本地化与状态恢复
- 设备语言自动识别
- 支持 Top 10 语言
- 无法读取时默认英文
- 保存最近一次模式、亮度、自定义模式列表

#### F. 品牌与视觉系统
- 统一使用当前原创四灯珠品牌素材
- 延续深色背景 + 柔光主画面 + iOS 风格玻璃控件
- 强化 `Soft Light` 作为品牌而不是小工具的感知

### 2.3 MVP 范围
- 12 个预设模式
- 全屏纯色柔光显示
- 左右滑动切换模式
- 上下滑动调节亮度
- 色盘展开与自定义模式保存
- 定时关闭
- 多语言自动切换
- 最近状态持久化
- Android APK 构建与模拟器验证

### 2.4 非 MVP 范围
- 广告 SDK
- Pro / 内购支付
- 账号体系
- 云同步
- 社区内容

## 3. 页面与流程设计
### 3.1 页面地图
- `AppRoot`
  - `SoftLightHomePage`
    - 顶部品牌栏
    - 全屏灯光区域
    - 手势反馈层
    - 底部单行模式控制条
    - 色盘抽屉
    - 保存模式弹窗
    - 定时选择弹层

### 3.2 核心路径
#### 路径 A: 默认点亮
- 启动 App
- 读取本地状态
- 读取失败时回退到默认浅白模式
- 进入主界面并立即显示柔光

#### 路径 B: 快速切模式
- 用户在灯光区左右滑动
- 模式即时切换
- 底部控制条同步更新选中态
- 当前模式名称与色点保持一致

#### 路径 C: 快速调亮度
- 用户在灯光区上下滑动
- 亮度实时调整
- 顶部或轻提示文案反馈当前亮度百分比

#### 路径 D: 创建自定义模式
- 点击色盘图标
- 打开底部抽屉
- 调色后点击 `Apply`
- 点击 `Save as My Mode`
- 输入名称并保存
- 新模式插入自定义列表首位

#### 路径 E: 使用定时关闭
- 点击定时入口
- 选择时间档位
- 主界面显示剩余时间状态
- 倒计时结束自动关闭灯光

### 3.3 异常路径
- 设备语言读取不到: 回退英文
- 本地存储解析失败: 忽略坏数据并回退默认状态
- 自定义模式数量超限: 提示覆盖最早项
- 应用切到后台再回来: 恢复当前灯光和倒计时状态

### 3.4 空状态与失败状态
- 自定义模式为空: 仅显示系统预设，不显示空白占位卡片
- 定时未启动: 不展示剩余时间标签
- 保存失败: 弹出轻量错误提示，不阻断当前灯光使用

## 4. 风格设计
### 4.1 设计关键词
- iOS 26 风格
- 纯净
- 柔和
- 轻玻璃感
- 高级而不复杂

### 4.2 颜色与氛围
- 基础背景: 深蓝黑而非纯黑，保证柔光更显色
- 主灯区域: 纯色直出，不加灰边、不加渐变、不加厚重阴影
- 控件底板: 半透明深色 + 轻模糊
- 选中态: 使用明亮蓝作为系统式强调色

### 4.3 字体与组件基调
- 使用 Cupertino / SF 系列系统字形，保持 iOS 一致性
- 标题大字，信息层级明确
- 按钮与 chips 采用圆角胶囊样式
- 色盘抽屉采用顶部大圆角 + 毛玻璃处理

### 4.4 动效原则
- 模式切换即时生效，不做拖沓过渡
- 抽屉展开采用短时位移 + 模糊过渡
- 亮度反馈使用轻量文本变化，不做额外复杂动画
- 所有动效以“响应快”优先，不追求花哨

### 5.2 状态管理方案
- 不引入额外状态管理包。
- 使用 `ChangeNotifier + AnimatedBuilder / ListenableBuilder` 管理主页面状态。
- 原因:
  - 当前应用为单核心页面
  - 状态主要是 UI 本地态和持久化态
  - 可以降低依赖复杂度，利于快速稳定交付

### 5.3 路由方案
- 使用 `CupertinoApp` 单主页结构。
- 弹层采用:
  - `showCupertinoModalPopup`
  - `showCupertinoDialog`
- 当前版本不引入命名路由，不增加多页面导航负担。

### 5.4 数据存储方案
- 使用 `shared_preferences` 保存本地轻量状态。
- 存储内容:
  - 当前默认模式 ID
  - 当前是否使用自定义模式
  - 当前亮度
  - 自定义模式列表
  - 上一次定时选项
- 不使用数据库，避免小应用过度设计。

### 5.5 网络层方案
- 当前版本无远程接口。
- 不接广告、不接支付、不接云同步。
- 所有运行逻辑离线可用。

### 5.6 关键依赖包及原因
- `shared_preferences`
  - 持久化当前模式和自定义颜色
- `flutter_colorpicker`
  - 提供成熟的 HSV 调色能力，减少自绘成本
- `flutter_localizations`
  - 支持系统语言适配和基础本地化能力
- `cupertino_icons`
  - 维持 iOS 风格图标统一

### 5.7 现有代码重构策略
- 保留已有可用逻辑:
  - 语言解析
  - 自定义颜色保存
  - 左右 / 上下手势基础实现
- 重构重点:
  - 将 `main.dart` 中模型、状态、UI 分层
  - 将预设配置抽离为独立数据源
  - 将色盘弹层、模式条、灯光画布拆为独立组件
  - 为定时器与状态恢复补齐模型与测试

## 7. 开发计划
### 7.1 迭代拆分
#### 迭代 1: 工程重构与主界面稳定
- 抽离状态和模型
- 保持现有功能不回退
- 确保默认纯色灯光区、模式条和基础手势稳定

#### 迭代 2: 高级控制与定时
- 实现色盘抽屉重构
- 实现定时关闭
- 完成最近状态恢复

#### 迭代 3: 本地化与测试补齐
- 校准 Top 10 语言文案
- 增加单元测试和部件测试
- 统一视觉细节和交互反馈

#### 迭代 4: 构建验证
- `flutter test`
- `flutter build apk`
- 模拟器安装验证
- 对照 PRD 与开发文档做一致性检查

### 7.2 模块优先级
- P0:
  - 主灯光显示
  - 模式切换
  - 亮度手势
  - 色盘与自定义保存
  - 定时关闭
- P1:
  - 状态恢复
  - 语言适配完整性
  - UI 重构与组件化
- P2:
  - 埋点抽象
  - 商业化预留位

### 7.3 风险点
- 现有逻辑集中在单文件，重构时容易引入回归
- 手势判定同时处理水平和垂直，需避免误触
- 定时器在前后台切换时需要正确恢复剩余时间
- 多语言文案长度差异可能影响控制条布局
- 安卓模拟器对全屏纯色截图可能存在显示偏差，但不影响实际运行

### 7.4 回退方案
- 在重构过程中保留现有模式数据和本地化文件
- 若新状态控制器引入回归，可先回退为单页状态实现，再逐步拆分
- 若定时功能影响稳定性，可临时下沉为次级弹层，不阻塞主灯光路径
